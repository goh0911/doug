# 縦スクロール型リーダー対応 設計

日付: 2026-10-06 / 状態: ドラフト（ユーザーレビュー待ち）

## 背景と目的

Marvel Unlimited（2026-12-07 に閲読終了）の後継「Marvel Comics powered by WEBTOON」
（marvel.webtoon.com, 2026-11-16 公開）は、WEBTOON 系の縦スクロール型ビューアである可能性がある。
Doug は現在「画面に 1 枚の画像（めくり型）」を前提としており、縦に画像が並ぶリーダーでは
画面内の最大 1 枚しか翻訳できない。**めくり型の動作を変えずに、縦スクロール型も翻訳できる**ようにする。

新リーダーの DOM は 2026-11-16 まで未確認である。本 spec は DOM に依存しない部分だけを確定し、
DOM 依存の判断は実測後に回す（「未決事項」参照）。

## 合意済みの要件

- 翻訳ボタンで、**見えている画像すべて**を翻訳する。
- `prefetch` 設定が ON のとき、**下方 N 枚（既定 N=2）**を先読みする。OFF なら可視画像のみ。
  ボタンで押した可視画像の翻訳は `prefetch` 設定に関係なく動く。
- めくり型の動作は変えない。
- 既存の翻訳・キャッシュ・Port 経路・課金の仕組みは変えない。

## 仮置きの判断（レビューで覆してよい）

- スクロールで新しく可視になった画像の翻訳は、既存の**自動翻訳トグル**（ツールバー、セッション状態）に従う。
  トグル OFF ならボタンを押したときだけ翻訳する。
- 1 回のボタン操作で翻訳する可視画像は最大 6 枚。超過分はスクロールで可視になった時点で順次処理する。

## 構成

| ユニット | 役割 | 依存 |
|---|---|---|
| `utils/scroll-select.js`（新規・pure） | 矩形配列と viewport から `{ visible, ahead, mode }` を返す。`mode` は `'single'` か `'scroll'` | なし（`chrome.*` 非依存） |
| content.js：候補収集 | 既存 4 グループ（blob img / svg image / img / canvas）から、サイズ条件を満たす全候補の要素と矩形を集める | 既存の判定を流用 |
| content.js：オーバーレイ管理 | 画像要素をキーにグループ化。描画・位置追従・消去を画像単位にする | 既存 `renderOverlays` / `observePosition` / `clearOverlays` を拡張 |
| content.js：翻訳ロック | `isTranslating` を画像単位（要素 or URL をキーにした Set）にする | 既存 `translateImage` |
| 先読み | 通常 URL は既存 `PRELOAD_QUEUE` に下方 N 枚の URL を渡す。blob は既存のセーフモード先読み経路に載せる | `prefetch` 設定 |

- 「どの画像を対象にするか」は `scroll-select.js` に閉じ込め、単体テスト可能にする。
- `mode === 'single'`（可視 1 枚で下方に続く画像なし）は従来の単一画像経路に入る。
  `'scroll'`（可視 2 枚以上、または下方に画像が続く）のときだけ新経路に入る。判定規則は 1 か所に置き、実測後に調整できるようにする。
- `scroll-select.js` を content.js にコピーする場合は `tests/unit/copy-sync.test.js` の `COPIES` に 1 行足す。
- 既存の `findNextBlobImages` は横めくり前提（viewport 右外）なので、縦スクロールでは使わない。
  下方の判定は `scroll-select.js` の `ahead` を使う。

## データフロー

1. 翻訳ボタン押下 → 候補収集 → `scroll-select.js`。
2. `visible[]` を上から順に、画像ごとに「キャッシュ確認 → 翻訳 → 当該グループへ描画」。先に終わった画像から表示する。
3. `prefetch` ON なら `ahead[]` を先読みする。通常 URL は `PRELOAD_QUEUE`（直列・最大 50 件・間隔 4.2 秒のまま）、blob は canvas 変換して Port 送信。
4. スクロール停止後（デバウンス）に再判定し、新たに可視になった画像を自動翻訳トグルに従って処理する。先読み済みならキャッシュヒットで即表示。
5. 画面外に出た画像のオーバーレイは保持し、画像に追従させる。
6. 失敗はその画像だけエラー表示にし、他の画像は止めない。
7. コスト上限：1 回のボタン操作で可視最大 6 枚（仮置き）。

## エラー処理

- 画像ごとに独立。1 枚の失敗（Vision API エラー、capture 失敗、JSON 破損）が他に波及しない。
- 翻訳中に画像が DOM から消えた／差し替わった場合、そのグループを破棄し、結果は捨てる。
- 画像要素のキー化は要素参照を基本とし、URL が同一の別要素（再描画）は URL キャッシュで吸収する。
- SPA 遷移（話の切り替え）では全グループを `clearOverlays` と同様に破棄する（既存のページ変更検知を流用）。

## テスト方針

- 単体（Vitest）：`scroll-select.js` を、矩形の合成入力で検証する。
  - 可視 0 / 1 / 複数枚、下方 N 枚の切り出し、画像が N 枚未満、上方の画像は含まない、
    閾値境界（最小サイズ 200×200・viewport の 10%）、`mode` の判定。
  - 陽性対照：めくり型に相当する入力（可視 1 枚・下方なし）が `'single'` を返すこと。
- コピー同期：content.js にコピーした場合は `copy-sync.test.js` で突き合わせ。
- 結合：`chrome.*` をモックして background.js 側の配線（先読みキューに渡る URL が `ahead` と一致）を検証する。
- E2E：既存 `MARVEL_WEBTOON_URL` のテストに「複数オーバーレイ」の確認を足す（URL は公開後）。
  実リーダーでの目視確認は 2026-11-16 以降に `tools/reader-diag.js` と併せて行う。
- 測定の規律（プロジェクト CLAUDE.md）：選択規則を診断ツール側に再実装しない。診断は本番の `scroll-select.js` を import して使う。

## 未決事項（2026-11-16 以降の実測で決める）

1. **縦長画像の分割**：1 画像が極端に縦長な場合、captureMaxDim（クラウド 1024px / Ollama 2048px）への縮小で文字が読めなくなる可能性がある。
   タイル分割（重なりを持たせる）の要否は、実画像の寸法を測ってから判断する。それまでは分割しない。
2. **吹き出しが画像の境界をまたぐ場合**の扱い（分割した場合のみ問題になる）。
3. **モード判定の規則**：スクロールコンテナの構造、画像の並び（隙間なし連続配置か）に応じた調整。
4. **画像の遅延読み込み**：下方 N 枚が未ロードの場合（`naturalWidth` 0）の扱い。
5. **シリーズ名の取得**：title / og:title / h1 の書式。`utils/url-pattern.js` に adapter を足すかどうか。
6. 利用規約（WEBTOON / Marvel）の自動化・キャプチャに関する条項の確認。

## スコープ外

- めくり型の動作変更、翻訳・キャッシュ・課金の仕組みの変更。
- 新リーダー専用の DOM 前提の実装（実測前）。
- 先読み枚数 N の設定 UI（既定 2 の固定値。必要になれば別途）。
