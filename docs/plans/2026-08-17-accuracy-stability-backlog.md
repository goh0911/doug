# 精度・安定性の改善候補（2026-08-17 時点）

2026-08-15〜17 の調査で判明した改善余地を、**測定の裏付けの有無**とともに整理する。
実測値は M1 Max 32 GB / Ollama 0.32.13 / qwen3.6:35b-a3b（推奨モデル）で取得。

## 検証の律速：難しい評価ページが無い

**これが最優先の課題。** 手元にある実ページ（Immortal Hulk 1 枚）は、現状の設定で
すでに満点を取ってしまう。

| 条件 | 検出 | 正解一致 | 文字一致率 |
|---|---|---|---|
| 1024px・前処理なし（3 回） | 14/14 | 14/14 | 100.0% |
| 1024px・前処理あり（3 回） | 14/14 | 14/14 | 100.0% |

**満点同士では、どんな改善を入れても差が出ない。** MAX_DIM を 2048 に上げた効果も、
前処理の是非も、このページでは永久に判定できない。

過去に「1024px で 6/8」を記録したのは 2514×1920 の別ページ（2026-08-13）。つまり
改善は「難しいページ」でのみ効く。**現状で満点を取れないページを 2〜3 枚確保する
ことが、以降すべての検証の前提になる。**

望ましい条件: 小さい文字 / 暗い背景の吹き出し / 手書き風フォント / 効果音が多い。
**実際に誤訳や取りこぼしが出たページが最良。**

## A. 用語集・解説

### A-1. 層A（プロンプトへの用語集注入）が機能していない ★最大

用語集 184 語のうち **`approved` が 0 語**。`buildSeriesPromptSection` は
`approved === true` の語だけをプロンプトに載せるため、**訳語の統一が一切効いていない**。
「ハルク」で統一したくても、モデルは毎ページ自由に訳している。

原因は承認ボタンが用語集 2 KB 上限で無言失敗していたこと。上限は 64 KB に修正済み
（a056878）だが、**過去に承認できなかった語は未承認のまま残る**。

対応の選択肢（いずれも設計判断が必要）:
- 一括承認の UI を用意する
- 自動抽出の信頼度が高いものを自動承認する
- 層A の条件を `approved` から緩める（**危険**: 誤った訳語が全訳文に波及する）

184 語を手で承認するのは非現実的。**効果は全ページに及ぶので費用対効果は最も高い。**

### A-2. 用語集ノイズ

クレジット頁由来の語が登録されている。実データで確認したもの:

| 語 | 実体 |
|---|---|
| `VC` | Virtual Calligraphy（写植会社） |
| `MARVEL` | 出版社 |
| `AL EWING` / `ALEX ROSS` | 原作者・作画家 |
| `ABSOLUTE CARNAGE` | 作品名 |
| `WYOMING FACILITY` | 「ワイオミングの施設」＝固有名詞ですらない |

害は限定的（解説自体は正確に作られる）だが、生成の無駄になる。抽出側で弾く規則は
誤検出のリスクがあるため、慎重に設計する必要がある。

### A-3. 曖昧語で別人の記事を引く

`AMADEUS` → Baron Mordo の記事。本名が **Karl Amadeus Mordo** で、導入節の主語に
"Amadeus" が含まれるため `termAppearsIn` が正当に通る。**ゲートの実装は正しく、
語そのものが曖昧なのが原因。**

タイトル一致を必須にする案は使えない。`RED HULK → Thunderbolt Ross` のように
別名（`aliasPhrases`）経由で正しく通っている例を巻き添えにする。

実データ 33 件の全件点検では、タイトルに語を含まない 15 件のうち**明確な誤りは
AMADEUS のみ**。残りは正当な別名立項だった（BLONSKY→Abomination、CARL/CREEL→
Absorbing Man、LEONARD→Doc Samson、CORTEZ→Weapon H など）。
`DOC DOOM → Doctor Doom in other media`（派生記事を掴む）は要検討。

### A-4. 訳語の重複（大小文字以外）

`WALT` と `WALTER` がどちらも「ウォルター」。大小文字の重複（`ROXXON`/`Roxxon`）は
3886701 で今後の登録を防ぎ、43a16fa で引き方も揃えたが、**別綴りの重複は残る**。
下線は 1 語ぶんしか出ないのに解説は語の数だけ生成される。

### A-5. 新しい作品は用語集がゼロから始まる

抽出は `recentPairs` が 20 件に達してから走る。実測:

| シリーズ | 用語集 | 翻訳回数 | 抽出実行 | recentPairs |
|---|---|---|---|---|
| Immortal Hulk (2018) | 184 語 | 222 | 105 | 4 |
| Civil War: Unmasked | 0 語 | 3 | 0 | 16 |
| Wade Wilson: Deadpool | 0 語 | 1 | 0 | 7 |

**欠陥ではなく仕様どおり**（あと数ページ読めば走る）。シリーズ横断（52c168d）で
既存作品の用語集は使えるようになったので、実害はかなり減っている。閾値を下げると
抽出の質が落ちるトレードオフがある。

### A-6. 素材が存在しない語

`SHOCK ROXX RADIO`（作中架空のラジオ局）は Wikipedia に記事が無く、原理的に成功
しない。24 時間ごとに再試行され続ける。失敗の連続回数でバックオフを伸ばす案がある。

## B. 本体の翻訳

### B-1. bbox の精度（未測定）

オーバーレイが吹き出しからはみ出すと読みにくい。合成画像では qwen3.6 が 3/4
（平均 IoU 0.62）だったが、**合成画像の評価は当てにならない**と分かっている。
実ページでの評価には吹き出し位置の正解データが要る（人手アノテーション）。

### B-2. 画像の前処理（判定不能）

`ctx.filter = 'contrast(1.4) brightness(1.05)'` が既定で有効。実ページの A/B では
**前処理あり・なしとも 3 回すべて満点**で差が出なかった。

「効果が測れなかった」であって「効果が無い」ではない。暗い吹き出しのページでは
効く可能性が残る（そもそもそれを想定した処理のはず）。**難しいページでの再測定待ち。**

### B-3. クラウド API の解像度は 1024 のまま

Ollama は 2048 に引き上げ済み（8a7c8a5）。クラウドはトークン課金が画素数に比例する
ため据え置いた（Claude は概ね w×h/750 トークン）。難しいページで精度差が確認できたら、
費用と引き換えに上げる判断はありうる。

### B-4. キャッシュが壊れた応答を永続化する

モデルが一度おかしな応答を返すと、そのページを開くたびに再現する。**復旧手段は
既にある**（ページ右下の再翻訳ボタンが `forceRefresh` でキャッシュを迂回）。
8f5d421 で説明文と README に明記した。

退化検出の実装は見送った。実データでは正常（異なり訳文の比率 0.77〜1.00）と退化
（0.17／0.20）が明確に分かれるが、**退化の標本が 2 件しかない**。同じ効果音が並ぶ
ページを誤検知すると正しい翻訳を黙って捨てる。1 クリックで復旧できる問題に対して
その不確かさを抱える価値がない。

## C. 安定性・環境

### C-1. `OLLAMA_ORIGINS` が Mac の再起動で消える

Ollama の既定の許可オリジンは `127.0.0.1` と `0.0.0.0` のみで `chrome-extension://`
を含まない。`launchctl setenv` はログインセッション限りなので、再起動のたびに
403 が再発する。Doug 側は 403 を検出して復旧コマンドを案内する（f1bc647）。
恒久化するには LaunchAgent が要る（利用者の環境設定なので Doug の範囲外）。

### C-2. 推奨モデルの安定性は良好

qwen3.6:35b-a3b は実ページ 3 回で **3314 字がバイト単位で同一**。温度 0 での
再現性は極めて高い。一方 Qwen3.8-27B の MLX 版は約 3 回に 1 回、構文的に壊れた
JSON を返した（そのため選択肢から削除済み）。

**モデル由来の不安定性より、環境要因（403・WebP 拒否・バージョン差）のほうが
実害が大きかった。** いずれも今回対処済み。
